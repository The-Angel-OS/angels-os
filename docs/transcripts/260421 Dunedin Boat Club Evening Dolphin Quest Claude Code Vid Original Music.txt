🛠️ HOW IT WAS BUILT

**Tooling:** Claude Code (Opus 4.7) orchestrating ffmpeg from a terminal. No timeline, no preview render, no project file.

**Step 1 — Lossless concatenation.** Five source clips, all H.264 / 3840×2160 / 60 fps / yuv420p / AAC 48 kHz stereo. Confirmed identical via ffprobe, then joined with the concat demuxer at `-c copy`. Zero re-encode. Minutes, not hours.

**Step 2 — Music bed.** 19 MP3s concatenated and re-encoded into a single AAC m4a (192 kbps, 48 kHz stereo) — long enough to cover the full 54:02 video without looping.

**Step 3 — Single-pass mix.** One ffmpeg `filter_complex` graph:
- `volume='if(lt(t,60),0.30,0.10)':eval=frame` — music at 30% for the first minute, then 10% for the rest, evaluated per audio frame.
- `amix=inputs=2:normalize=0` — sums the original audio (full level) with the volume-shaped music bed. `normalize=0` is critical — without it, ffmpeg auto-halves both inputs and buries the voices.
- `-c:v copy` — video stream untouched.
- `-shortest` — output ends with the video.

**Why this beats a ClipChamp export:** ClipChamp (and most NLEs) decode-and-re-encode H.264 even when you're "just" mixing audio. On a 54-minute 4K60 file that's a generation of quality lost and hours of compute. Stream copy was minutes. The recipe is deterministic, scriptable, and runs again tomorrow on any folder by changing two paths.
